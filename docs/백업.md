# DB 백업

- 백업: `bash qa/db-backup.sh` → `backups/daily/erp-YYYYMMDD-HHMM.dump` (pg_dump -Fc, 본사 + 회사 스키마 전부).
  보관은 최근 7개 + 주마다 1개씩 4주. 100KB 미만이거나 pg_dump 가 실패하면 0 이 아닌 값으로 끝난다.
- 복원 시험: `bash qa/db-restore-test.sh` — 가장 새 덤프를 임시 DB `erp_restore_test` 에 붓고 건수를 운영과 나란히 찍은 뒤 지운다(운영 DB 는 읽기만).
- 실제 복원(운영 DB 를 덮어씀): `bash qa/db-restore.sh <덤프>`.

## 다른 곳에 한 벌 더

`ERP_BACKUP_COPY_DIR` 에 NAS · OneDrive · 외장 디스크 폴더를 주면 새 덤프를 거기에도 복사하고 같은 보관 규칙을 적용한다.
예: `/d/OneDrive/erp-backup`. 덤프에는 비밀번호 해시가 들어 있으니 본인만 보는 곳으로.

## Windows 작업 스케줄러 등록 (매일 18:00) — 직접 한 번 실행

```
schtasks /Create /TN "ERP DB Backup" /SC DAILY /ST 18:00 /F /TR "\"C:\Program Files\Git\bin\bash.exe\" -lc \"cd /c/Users/USER/Desktop/manufacturing-erp && ERP_BACKUP_COPY_DIR=/d/OneDrive/erp-backup bash qa/db-backup.sh >> backups/backup.log 2>&1\""
```

복사 폴더가 없으면 `ERP_BACKUP_COPY_DIR=... ` 부분을 뺀다. 지우기: `schtasks /Delete /TN "ERP DB Backup" /F`.
Docker Desktop 과 `erp-postgres` 컨테이너가 떠 있어야 한다. 가끔 `qa/db-restore-test.sh` 로 되살아나는지 확인할 것.
