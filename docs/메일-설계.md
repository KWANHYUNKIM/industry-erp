# 웹메일 설계 — 회사 도메인(@farm-in.kr)으로 주고받는 메일

2026-10-31 작성. 이카운트 Webmail(부가 서비스)을 밖에서 분석한 결과와, 우리 ERP 에 같은 기능을 붙이는 방법.
가격 · 무료 한도는 **이 문서를 쓴 날 기준 추정**이다 — 실제로 고르기 전에 각 서비스 요금표를 다시 확인한다.

---

## 1. 이카운트는 어떻게 되어 있나 (밖에서 본 것)

로그인 없이 DNS · HTTP 머리 · 로그인 화면만 봤다.

| 항목 | 관찰 | 뜻 |
|---|---|---|
| 웹메일 | `wmail.ecount.com` → 43.200.46.3 (`ec2-…ap-northeast-2.compute.amazonaws.com`) | AWS 서울 EC2 |
| ERP | `loginad.ecount.com` → 13.124.7.42 (서울 EC2) | 웹메일과 **다른 서버** |
| 웹 서버 | `server: Kestrel`, 쿠키 `SVID=AWSWebUI`(ERP 는 `SVID=Login-A`) | ASP.NET Core. 서버 묶음 이름표로 부하 분산 |
| 정적 파일 | `resource.ecount.com` → `AmazonS3` + `CloudFront` | 화면 JS 는 S3 + CDN, ERP 와 같은 `ecountv5` jQuery 묶음 |
| 고객 MX | `farm-in.kr MX 10 wmx.ecount.com` (= 웹메일과 같은 EC2) | 고객 도메인으로 오는 메일을 이카운트가 받는다 |
| 고객 SPF | `v=spf1 mx include:spf.ecount.com ~all` | 이카운트 서버가 고객 이름으로 보내도 된다는 허가 |
| 발송 서버 | `spf.ecount.com` = EC2 고정 IP 8개 + `spf3.ecount.com` | **자체 발송**(SES 였다면 `include:amazonses.com`) |
| 로그인 연결 | `/webmail_login_processor` 를 직접 열면 403 | ERP 로그인 상태에서 넘기는 토큰으로만 들어간다. 별도 아이디 로그인 화면도 있다 |
| IMAP/SMTP 제출 포트 | 바깥에서 응답 없음 | 메일 앱 연결 길은 막혀 있거나 다른 주소(확실치 않음) |
| 판매 방식 | ERP [Email] → 미가입 회사는 안내 창('10명 당 5천원, 20GB · 마스터ID만 신청') | 회사 단위로 **열어 주는** 유료 부가 서비스 |

정리하면 **ERP 와 떨어진 별도 서비스**(웹메일 + 메일 받기 + 발송을 자체 EC2 로 운영)이고, 고객은 DNS 두 줄(MX · SPF)만 넣는다.
그 안이 잘게 쪼갠 MSA 인지는 밖에서 알 수 없다 — 받기와 웹이 한 서버라 오히려 덩어리에 가깝다.

## 2. 고객 도메인 메일이 되는 원리

도메인 주인이 DNS 에 넣는 기록:

| 기록 | 하는 일 | 없으면 |
|---|---|---|
| MX | 그 도메인으로 오는 메일을 우리 받는 서버로 | 메일을 못 받는다 |
| SPF (TXT) | 우리 발송 서버가 그 도메인 이름으로 보내도 됨 | 받는 쪽이 스팸 처리 · 거부 |
| DKIM (TXT/CNAME) | 보낸 메일에 서명 — 위조 아님 증명 | Gmail · 네이버가 스팸으로 보내기 쉽다 |
| DMARC (TXT) | SPF · DKIM 이 안 맞을 때 받는 쪽 정책 | 2024 년부터 대량 발송은 사실상 필수 |

우리 화면은 "이 기록을 DNS 에 넣으세요" 를 보여 주고, [확인] 으로 들어갔는지 검사한다.

## 3. 만드는 방법 — 세 갈래

### A. 유료 관리형: AWS SES (추천 — 운영 부담 가장 적음)

- 보내기: SES API. 고객 도메인을 SES 에 등록하면 DKIM 기록 3줄을 준다.
- 받기: MX → SES 수신(inbound) → S3 에 원문 저장 → SNS/SQS 알림 → 우리 백엔드가 원문을 풀어 받은 메일함에 넣는다.
- 비용: 발송 건당 소액(천 건당 수십 원 수준), 수신도 건당 소액. 소규모면 월 몇 천 원 이하로 예상.
- 주의: 처음엔 샌드박스(인증된 주소에만 발송) — 서비스 전에 **발송 한도 해제 신청**. SES 수신은 일부 리전만 된다 — 서울 지원 여부 확인, 안 되면 받기만 지원 리전에.
- 메일 앱(IMAP) 연결은 안 된다 — ERP 안에서만 메일을 쓴다(이카운트도 사실상 이 모습).

### B. 무료 소프트웨어 직접 운영 (이카운트와 같은 방식)

오픈소스 메일 서버를 우리 서버에 띄운다. **소프트웨어는 무료, 서버 · 운영은 우리 몫.**

| 후보 | 특징 |
|---|---|
| Stalwart Mail Server | 한 바이너리에 SMTP · IMAP · JMAP · 스팸필터 · DKIM. 관리 화면 있음. 가장 간단 |
| Mailcow (Docker) | Postfix · Dovecot · Rspamd · SOGo 웹메일 묶음. 기능 많고 무겁다(메모리 4GB+ 권장) |
| Postfix + Dovecot | 표준 조합. 설정을 다 손으로 |

- 우리 ERP 는 IMAP/SMTP 로 붙는다(Jakarta Mail). 메일 앱(Outlook · 휴대폰)도 그대로 붙는다 — 이게 장점.
- **어려운 점(무료지만 비싼 부분):**
  - 25번 포트: AWS EC2 는 기본으로 바깥 25번 발송을 막는다 → AWS 에 해제 신청. 가정용 인터넷은 대개 막혀 있다.
  - 고정 IP + 역방향 DNS(PTR) 설정, IP 평판 관리 — 새 IP 는 처음에 Gmail · 네이버가 스팸으로 보내기 쉽다.
  - 스팸 · 바이러스 필터, 백업, 보안 업데이트, 장애 대응을 우리가 한다.
- 절충: **받기는 자체 서버, 보내기만 SES/외부 릴레이**로 보내면 평판 문제는 줄고 메일 앱도 붙는다.

### C. 무료 외부 서비스 조합 (돈 거의 안 듦, 대신 제약)

| 용도 | 서비스(무료 한도는 바뀔 수 있음) | 제약 |
|---|---|---|
| 받기(전달만) | Cloudflare Email Routing | 도메인 DNS 가 Cloudflare 에 있어야 함. **메일함이 아니라 다른 주소로 넘겨 줄 뿐** |
| 받기 → 우리 서버 | Cloudflare Email Workers | 받은 메일을 코드로 우리 API 에 넘길 수 있다 — 우리 DB 메일함으로 넣기 가능 |
| 보내기 | Brevo · Mailgun · SES 프리티어 등 | 하루 · 월 발송 수 제한, 발신 주소 인증 필요 |
| 메일함 통째 | Zoho Mail 무료 플랜 | 사용자 수 제한, 무료는 IMAP · 앱 연결 제한이 있었음 — ERP 연동 어렵다 |

- 시험 · 사내용으로는 C 로 거의 공짜에 돌릴 수 있다(받기 = Cloudflare Email Workers → 우리 API, 보내기 = 무료 발송 한도).
- 고객에게 **파는** 서비스라면 무료 한도 · 약관(재판매 금지 등) 때문에 A 나 B 로 가야 한다.

### 고르는 기준

| 상황 | 추천 |
|---|---|
| 일단 우리 회사만, 돈 안 들이고 | C (Cloudflare 받기 + 무료 발송) |
| 고객에게 팔 것, 운영 인력 적음 | A (SES) |
| 메일 앱 연결 · 이카운트와 똑같이 · 운영 가능 | B (Stalwart) + 보내기만 SES |

## 4. 우리 ERP 쪽 설계 (A · B · C 공통)

지금 상태: `groupware/mail`(`Mail` · `MailType` INTERNAL/SHARED · `MailStatus` · `SpamRule`) — 사내메일 · 공용메일을 **우리 DB 안에서만** 주고받는다. 바깥 메일 서버와 연결 없음.
앱바 [Email] 은 원본 안내 문구(`features/appbar/AppBar.tsx` `EMAIL_NOTICE`)를 띄운다.

### 4.1 회사별 열어 주기 (유료 게이트)

- 본사(`public`)에 `company_services`(company_id · service=`WEBMAIL` · enabled · seat_limit · quota_mb · started_at · ends_at). 마이그레이션은 `db/migration` 에.
- 본사 관리자 화면: 회사별 [열기/닫기] · 계정 수 · 용량. "마스터에게 문의 → 열어 줌" 이 이것.
- 서버: 웹메일 API 는 이 표로 막는다(꺼진 회사 → 403 + 안내 코드). 화면: 꺼진 회사는 지금처럼 `EMAIL_NOTICE`, 켜진 회사는 메일함.
- 결제 자동화(PG 정기결제)는 나중 — 처음엔 수동으로 열어 준다.

### 4.2 도메인 · 계정

- 회사 스키마(`db/tenant`)에 `mail_domains`(domain · verify_status · dkim 기록 · 마지막 확인 시각), `mail_accounts`(user_id · address · 상태).
- [도메인 추가] → 넣을 DNS 기록 표시 → [확인] 이 MX/SPF/DKIM 을 조회해 상태 갱신(A 는 SES 인증 상태 API).
- 사원 등록 시 `이름@도메인` 계정 만들기(계정 수 ≤ seat_limit).

### 4.3 보내기 · 받기

- `Mail` 에 바깥 메일을 담을 칸: `MailType.EXTERNAL`, message_id, in_reply_to, to/cc/bcc 주소 목록, 원문 저장 위치(S3 키 · 파일), 첨부(드라이브 저장 방식 재사용). 엔티티 · 마이그레이션은 본사 · 테넌트 둘 다(CLAUDE.md 7.4).
- 보내기: `MailSender` 인터페이스 — 구현 `SesMailSender`(A) / `SmtpMailSender`(B · C). 설정으로 고른다.
- 받기: `InboundMailHandler` — A 는 SQS 소비자가 S3 원문을 읽고, B 는 IMAP 동기화(처음엔 화면 열 때 가져오기, 나중에 백그라운드), C 는 Cloudflare Worker 가 우리 `POST /api/mail/inbound`(서명 검증)로 넘긴다.
- 원문 파싱: Jakarta Mail `MimeMessage`. HTML 본문은 서버에서 정화(sanitize)해 저장 — 받은 메일 HTML 을 그대로 화면에 그리면 XSS.
- 스팸: 기존 `SpamRule` 에 SPF/DKIM 결과(받는 쪽 헤더)를 더한다.

### 4.4 로그인 연결

이카운트처럼 별도 서비스로 떼더라도 ERP JWT 를 넘겨 바로 연다. 처음엔 **같은 백엔드 안 모듈**로 두고(분리 불필요),
사용자가 늘어 IMAP 동기화 · 수신 처리가 무거워지면 그 부분만 별도 작업 프로세스로 뺀다.

## 5. 단계

| 단계 | 내용 | 사용자가 할 일 |
|---|---|---|
| 1 | `company_services` + 본사 열기/닫기 화면 + [Email] 분기 | — |
| 2 | 도메인 등록 · DNS 안내 · [확인] | 도메인 DNS 관리 화면 접근 |
| 3 | 보내기(`MailSender`) | A: SES 도메인 인증 · 한도 해제 신청 / C: 무료 발송 서비스 가입 |
| 4 | 받기(`InboundMailHandler`) + 받은 메일함 | A: SES 수신 규칙 · S3 / B: 메일 서버 띄우기 / C: Cloudflare Email Routing · Worker |
| 5 | 첨부 · 스팸 · 용량 집계 · 결제 | PG 계약(결제 자동화 시) |

## 6. 정할 것

1. A · B · C 중 어느 길로 갈지(처음엔 C 로 시험 → A 로 판매가 무난).
2. 서버를 어디에 둘지(지금 개발 서버 · AWS 계정 유무).
3. 첫 고객 도메인 — `farm-in.kr` 은 지금 MX 가 이카운트(`wmx.ecount.com`)를 가리킨다. **바꾸면 이카운트 메일이 끊긴다** — 시험은 다른 도메인(또는 서브도메인 `mail.회사도메인`)으로.
