## 2. 토큰 · 세션 설계 제안

| 단계 | 내용 | 막는 것 |
|------|------|---------|
| **지금(하루)** | ① `JWT_SECRET` 폴백 제거 · 기동 시 길이 검사(H1) ② 필터에서 `isEnabled()` 검사(H6) ③ 사용자 `token_version` 컬럼 — 비번 변경 · 사용중지 · 권한 변경 · [강제 로그아웃] 때 +1, 토큰 클레임과 다르면 401 ④ 수명 8h → 업무시간 기준 유지하되 ③으로 회수 가능하게 | 공개 비밀로 위조, 퇴사자 토큰 |
| **단기(1~2주)** | **BFF + HttpOnly 쿠키**: 로그인 응답이 토큰 대신 `Set-Cookie: __Host-erp_sid; HttpOnly; Secure; SameSite=Strict` (서버 세션 또는 짧은 JWT). 프론트는 `withCredentials` 만, `localStorage` 토큰 삭제. CSRF 토큰(L1). 쿠키를 쓰기 싫으면 차선: **액세스 15분(메모리 보관) + 리프레시(HttpOnly 쿠키, 회전 + 재사용 탐지)** — 이미 쓴 리프레시가 다시 오면 그 사용자 토큰 묶음 전체 폐기. 리프레시 수명 = 보안정책 `sessionTimeout`(유휴) + 절대 수명(예: 12h). | XSS 토큰 탈취(M1), 세션 자동종료(M5) |
| **장기(SaaS 판매 전)** | 인증을 IdP(§3)로 넘기고, 우리 백엔드는 **리소스 서버**(JWKS 로 RS256 검증, `iss`/`aud` 확인, `tenant` 클레임 + 우리 DB 의 사용자 매핑). 브라우저는 계속 BFF 쿠키(Spring Cloud Gateway 또는 Spring Security `oauth2Login` 이 토큰을 서버에 보관). 감사 로그 · 세션 목록 · 원격 로그아웃 화면. | 비밀번호를 우리가 다루는 범위 축소, SSO/MFA |

참고: IETF *OAuth 2.0 for Browser-Based Applications* 는 브라우저 앱에 BFF 를 가장 안전한 형태로 두고 `localStorage` 같은 지속 저장을 경계한다.
RFC 9700(OAuth 2.0 Security BCP) 은 공개 클라이언트의 리프레시 토큰을 **회전(재사용 탐지)** 또는 송신자 제약으로 보호하라고 한다.
OWASP JWT Cheat Sheet(Java) 는 JWT 폐기가 본래 안 되는 문제와 폐기 목록 · 쿠키 지문 결합을 다룬다.

## 3. OAuth/OIDC · SSO 도입 선택지

| 선택지 | 장점 | 단점 | 우리에게 |
|--------|------|------|----------|
| A. 지금처럼 자체 로그인 + §2 단기 | 바로 할 수 있음, 원본(이카운트) 로그인 화면과 같음 | MFA · SSO · 소셜을 다 직접 | **1단계는 이것** |
| B. Spring Security `oauth2Login` 으로 소셜(구글 · 네이버 · 카카오) **연결만** 추가 | 의존성 적음, 자체 계정에 "소셜 연결" | 회사(테넌트)별 SSO 는 직접 짜야 함. 네이버 · 카카오는 OIDC 지원 범위가 달라 제공자별 처리 | 직원 개인 편의용. B2B ERP 에선 우선순위 낮음 |
| C. **Keycloak**(자체 호스팅 IdP) | MFA(OTP · WebAuthn) · 잠금 · 비번 정책 · 고객사 SAML/OIDC 연동(Identity Brokering) · 관리 화면 기성품. 테넌트 = realm 하나씩 또는 한 realm + Organizations 기능 | 운영할 서버 하나 더(JVM, DB), 업그레이드 부담, 8GB 개발 머신엔 무거움 | **SaaS 판매 시 추천.** 회사별 SSO 요구가 생기면 바로 대응 |
| D. Spring Authorization Server(직접 만드는 IdP) | 코드로 완전 제어, 같은 스택 | 로그인 · MFA · 관리 화면 · 연동을 거의 다 만들어야 함 | 인증 자체가 제품이 아니면 비추 |
| E. 관리형(Auth0 · Cognito · Entra External ID 등) | 운영 없음 | 사용자 수 과금, 한국 소셜 직접 지원 약함, 개인정보 국외이전 검토 | 비용 · 규제 보고 판단 |

**추천**: 지금은 A + §2(쿠키 · 회수 · 잠금 · 속도 제한). 보안정책의 **2단계 인증**은 TOTP(Google Authenticator 류)를 자체로 붙이는 게 가장 작다.
**외부 고객사에 팔기 시작할 때 C(Keycloak)** 로 옮기고, 회사코드 → realm(또는 organization) 매핑, 우리 백엔드는 리소스 서버로.
테넌트는 계속 **토큰 클레임 + 우리 `companies` 레지스트리 대조**로만 정한다(요청 값으로 못 바꾸는 지금 원칙 유지).

## 4. 운영 보안

- **비밀 관리**: 저장소엔 비밀 0 — JWT 키 · DB 비번 · 메일/외부 API 키는 환경변수 → 운영은 AWS Secrets Manager/SSM Parameter Store(또는 Vault). 기본값 폴백 금지, 없으면 기동 실패. 주민번호 암호화 키는 KMS, DB 와 다른 곳.
  공개 저장소이므로 **GitHub secret scanning · push protection** 켜기, 커밋 전 `gitleaks` 를 `qa/precommit.sh` 에.
- **로그 · 감사**: 로그에 비번 · 토큰 · 주민번호 금지(H5 179행). 감사 로그 표(누가 · 언제 · 어느 회사 · 무엇을: 로그인 성공/실패, 권한 · 마스터 변경, 사용자 생성/비번 초기화, 주민번호 원문 보기, 대량 내보내기). 500 은 추적 id 로 로그(M6).
- **네트워크**: DB 포트는 localhost/사설망만(H5), 앱은 HTTPS 뒤(리버스 프록시에서 TLS · HSTS · CSP).
- **백업**: `docs/백업.md` 기준 + 백업 파일 암호화 · 접근 제한, 테넌트 스키마 포함 복원 시험을 정기적으로. 백업에도 주민번호가 들어가므로 암호화 컬럼이 그대로 보호.
- **의존성 점검 자동화**: GitHub Dependabot(npm · maven) · `npm audit --omit=dev` · OWASP Dependency-Check maven 플러그인을 CI/주간 작업으로. 높음 이상이면 실패.
- **기준표**: OWASP ASVS 5.0 레벨 1을 체크리스트로(인증 · 세션 · 접근제어 장), API 는 OWASP API Security Top 10(2023) — 특히 API1 BOLA(M3) · API3 속성 단위 인가(H3 주민번호 응답) · API5 기능 단위 인가(H2 · H4).

## 5. 작업 순서 (높음부터)

| 순서 | 작업 | 확인 방법 |
|------|------|-----------|
| 1 | H1 JWT 비밀 폐기 · 폴백 제거 · 기동 검사 | `JWT_SECRET` 없이 기동 → 실패해야 함. 기존 토큰은 401(재로그인). |
| 2 | H5 시드 `@Profile("dev")` · 로그 비번 제거 · compose 포트 127.0.0.1 · DB 비번 환경변수 | 운영 프로필 기동 시 데모 계정 없음, `lsof -iTCP:5432` 가 `127.0.0.1`. |
| 3 | H6 `isEnabled()` · `token_version` | 사용중지/비번 변경 직후 기존 토큰 요청 → 401 (qa 흐름 하나 추가). |
| 4 | H4 마스터 · ADMIN 부여 · 마스터 비번 변경은 마스터만 | `USER_MANAGE` 만 준 시험 계정으로 마스터 지정 → 403. |
| 5 | H2 조회 인가를 서버 표로 · 민감 조회 `READ_GUARDED` | 권한 없는 계정 + 꾸민 머리로 사원 · 사용자 목록 → 403. `screen-check` 로 정상 화면이 안 깨지는지. |
| 6 | H3 주민번호 암호화 · 마스킹 · 원문 권한 (본사 + 테넌트 마이그레이션) | DB 에서 `resident_no` 가 평문 아님, 응답이 마스킹, `schema-check` 통과. |
| 7 | M2 DOMPurify · 서버 정화 · M1/§2 단기 쿠키 전환 | 위험 태그가 든 본문을 저장 → 화면에서 실행 안 됨, `localStorage` 에 토큰 없음. |
| 8 | M3 결재 등 `/{id}` 당사자 검사 | 당사자 아닌 계정으로 상세 → 403. |
| 9 | M5 로그인 잠금 · 속도 제한 · 보안정책 적용 | N회 실패 후 잠김, 정책 화면 값이 실제로 먹음. |
| 10 | M6 오류 응답 · 로그, M4 파일, M7 의존성, M8 세션 주소 정리 | 500 응답에 내부 문구 없음 · 로그에 추적 id, `npm audit --omit=dev` 0건. |
| 11 | L 항목 · §4 자동화(gitleaks · Dependabot · ASVS 체크리스트) | `precommit.sh` 에 포함. |

## 6. 정할 것

1. **저장소 공개 유지?** 공개면 비밀 · 시드 · 내부 문서(원본 화면 분석 · 접속 정황)가 계속 노출된다. 비공개 전환 여부.
2. 토큰 보관: **BFF + HttpOnly 쿠키**(추천) vs 메모리 + 회전 리프레시.
3. 세션 수명: 유휴 종료(보안정책 기본 30분)와 절대 수명 값.
4. 주민번호를 **꼭 저장해야 하나**(원천징수 · 4대보험 신고 근거로 필요 — 법정 근거 있는 화면만 저장, 나머지는 생년월일로).
5. 로그인 오류 문구를 원본처럼 회사코드 구분 유지할지(L4).
6. IdP 도입 시점(외부 고객사 첫 계약?)과 Keycloak realm-per-회사 vs organizations.
7. 2단계 인증 방식(TOTP 자체 vs IdP), 마스터에게 필수로 할지.
8. 감사 로그 보존 기간과 보는 사람.
