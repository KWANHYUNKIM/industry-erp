# QA 에이전트 — 원본 자료를 손으로 옮겨 넣으며 차이 찾기

목적은 **우리 회사 프로세스가 이카운트 프로세스와 같은지** 보는 것이다. 자료를 일괄로 밀어 넣지 않는다.
사람이 하듯 원본 화면에서 한 건을 읽고 → 우리 화면에서 같은 순서로 입력 · 저장 → 결과 화면(현황 · 재고 · 채권 · 장부)을 원본과 맞대 본다.

## 준비

1. 상태: `curl` 로 8081 · 5180 응답, `docker ps`. 꺼져 있으면 CLAUDE.md 9절대로 켠다.
2. 접속 정보: `.claude/skills/ecount-diff/plans/데이터이관/_접속.md` (우리 쪽 회사 0005 · 관리자 계정). 채팅에 비밀번호를 옮겨 적지 않는다.
3. 원본 주소: 인자, 없으면 `_접속.md` · `plans/재개.md` 맨 위 주소. Chrome 탭은 **보이는 탭 하나**에서 원본과 우리 앱을 번갈아 연다(숨은 탭은 스크린샷이 안 바뀜).
4. 진행 상황: `plans/데이터이관/_진행.md` 를 읽고 이어서 한다. 끝날 때 갱신한다.

## 순서 (기초 → 전표 → 대조)

1. **기초자료**: 부서 · 사원(담당) · 창고 · 품목그룹 · 품목 · 거래처그룹 · 거래처 · 프로젝트 · 계정 · 통장/카드 · 외화.
2. **전표**: 견적 → 주문 → 판매 / 발주 → 구매 / 생산(작업지시 · 생산불출 · 생산입고) · 이동 · 조정 / 입금 · 지급 · 일반전표 · 세금계산서.
   원본 전표를 **날짜 순서대로** 넣는다(재고 · 채권 잔액이 순서에 따라 달라진다).
3. **결과 대조**: 재고현황 · 재고수불부 · 판매/구매현황 · 채권/채무현황 · 거래처관리대장 · 합계잔액시산표 · 손익계산서 — 같은 기간 숫자를 원본과 맞대 본다.

모듈마다 원본 목록에서 **건수 · 대표 자료 몇 건**을 먼저 보고, 많으면 전부가 아니라 서로 다른 경우(통화 · 부가세 유형 · 반품 · 로트 · 다중 창고)를 고루 골라 넣는다. 고른 기준을 md 에 적는다.

## 원본 화면을 읽는 법

- 목록은 `get_page_text` 로 읽는다. 한 건의 상세는 그 전표를 열어 읽는다.
- **원본도 저장 · 수정 · 삭제해 봐도 된다**(2026-10-23 사용자 허락, loginaa 는 테스트 회사). 같은 조작을 원본과 우리 쪽에서 똑같이 해 보고 결과를 맞댄다.
  원본에 새로 만든 시험 자료는 적요 등에 `QA` 표시를 남기고, 대조가 끝나면 지운다. 원래 있던 자료를 고쳤으면 원래 값으로 되돌린다.
  쪽지 · 메일 · 결재 · 문자 같은 **남에게 가는 전송은 본인 계정끼리만** 한다.
- 원본 자료를 브라우저 밖(로컬 서버 · 파일 내려받기)으로 빼내지 않는다 — 자동 안전 검사가 막는다(2026-10-23 확인).
- 프로세스가 이해 안 되면 `D:\이카운트\` 를 본다: `_목차.md` 에서 모듈 · 메뉴를 찾고, 그 폴더의 `프로세스.md`(없으면 `자막.txt`)를 읽는다.
  폴더는 아직 모으는 중이라 늘어난다 — 있는 것만 보고, 없으면 "자료 없음" 이라고 적고 넘어간다. `grep -rl "<메뉴명>" "D:/이카운트" --include=프로세스.md` 로 찾는다.

## 우리 화면에 넣는 법

- 회사코드 0005 로 로그인해서 **화면으로** 넣는다. API 직접 호출 · DB 쓰기 금지(그게 이 QA 의 대상이다).
- 원본에 있는 값은 빠짐없이 넣어 본다. 넣을 칸이 없으면 그게 차이다.
- 저장 뒤 화면이 무슨 말을 하는지(안내 · 오류 · 아무 말 없음), 목록 · 현황에 어떻게 보이는지 본다.

## 기록 — `plans/데이터이관/<모듈>.md`

모듈 하나에 파일 하나(`재고1.md` · `회계1.md` …). 차이 하나에 한 칸:

```
### [심각도] 화면명 — 한 줄 요약
- 원본: 무엇을 했더니 어떻게 됐다 (메뉴 경로 · 값)
- 우리: 같은 것을 했더니 어떻게 됐다
- 고칠 것: 무엇을 어떻게 (짐작 가는 파일 경로가 있으면)
- 근거: 원본 화면 · `D:\이카운트\...\프로세스.md` 줄
```

심각도: **막힘**(입력 · 저장이 안 된다) · **로직**(숫자 · 재고 · 채권 · 회계 결과가 다르다) · **빠짐**(원본에 있는 칸 · 기능이 없다) · **모양**(글 · 배치만 다르다).
옮겨 넣은 자료는 `_진행.md` 에 '모듈 / 화면 / 원본 건수 / 넣은 건수 / 남은 것' 표로 남긴다.

**코드는 고치지 않는다.** 찾고 적는 것까지가 이 스킬의 일이다. 고치는 것은 `/finish` · `/ecount-diff` 가 이 md 를 읽고 한다.

## 진행 방식

- 진행자는 모듈 하나씩 작업자(하위 에이전트, `model: sonnet`)에게 맡긴다. 브라우저가 하나라 **작업자는 한 번에 하나**만 띄운다.
- 작업자 지시문: 이 SKILL.md 를 따르라 · 맡은 모듈 · 이어 할 곳(`_진행.md`) · 보고 형식(넣은 건수 · 찾은 차이 수 심각도별 · 막힌 것).
- 작업자가 끝나면 사용자에게 2~3줄 보고하고 다음 모듈로 간다. 멈출 때 `_진행.md` 맨 위에 '다시 시작할 곳' 을 쓴다.
