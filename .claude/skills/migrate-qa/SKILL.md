# 데이터이관 QA 한 바퀴 (QA → 코딩 에이전트 → 더블체크)

**목표: 원본 이카운트와 완전히 똑같이.** 같은 입력 → 같은 출력. 화면(칸 · 단추 · 메뉴 · 안내 문구 · 저장 뒤 동작)과
결과(금액 · 수량 · 잔량 · 재고 · 채권 · 회계 분개 · 번호 · 날짜)와 로직(전환 · 잔량 차감 · 상태 변화)이 하나라도 다르면 차이로 적고 고친다.
"비슷하다" 는 통과가 아니다. 원본에서 못 잰 것은 '미실측' 으로 적고 짐작으로 맞추지 않는다(2026-10-23 · 10-28 사용자).

## 스레드(모듈 나눠 맡기) — 2026-10-28 사용자 요청

원본을 보는 QA 는 메인 대화만 할 수 있어서(하위 에이전트는 loginaa 이동이 막힘), 모듈을 나눠 **대화(터미널)를 여러 개** 띄운다.

| 스레드 | 인자 | 진행 파일 | 현황판 | 기록 md |
|--------|------|-----------|--------|---------|
| A (기본) | 없음 또는 `재고1,회계1` | `_진행.md` | `_현황판.md` | `재고1.md` · `회계1.md` |
| B | `재고2,회계2,세무,그룹웨어,관리` | `_진행-B.md` | `_현황판-B.md` | `재고2.md` · `회계2.md` · `세무.md` · `그룹웨어.md` · `관리.md` |

- **자기 스레드의 진행 파일 · 현황판만 고친다**(동시에 같은 파일을 고치면 커밋이 꼬인다). 공통 파일(이 SKILL.md · `_접속.md`)은 고치지 않는다 — 고칠 일이 있으면 진행 파일에 적어 두고 사용자에게 말한다.
- 진행 파일이 없으면 첫 회차에 만든다: 맨 위 '다시 시작할 곳', 그 아래 진행표(`| 모듈 | 화면 | 원본 건수 | 넣은 건수 | 남은 것 |`) — `node qa/migrate-progress.mjs` 가 모든 `_진행*.md` · `_현황판*.md` 를 합쳐 센다.
- **B 스레드의 첫 회차들 = 원본 훑기**: 맡은 모듈마다 원본 메뉴(사이트맵)를 열어 기초등록 → 입력 → 조회 화면별 **원본 건수**를 세어 진행표 줄을 채우고, '경우 체크리스트'(`- [ ] …`)를 그 모듈의 서로 다른 경우로 만든다. 그다음부터 이 문서의 '한 바퀴' 그대로.
- 기초자료 순서: 관리(부서 · 사원 · 급여항목 …)는 다른 모듈이 기대므로 먼저. 회계2 · 세무는 회계1 자료(계정 · 전표)에 기대니 A 스레드의 회계1 진행을 `_진행.md` 에서 확인하고 겹치지 않게.
- 코더 · 관리자 에이전트는 스레드마다 따로 띄운다. **백엔드 코더는 두 스레드를 합쳐 한 번에 하나** — 띄우기 전에 `git log -3` · `git status` 로 다른 스레드의 백엔드 작업(마이그레이션 · 재기동)이 도는지 보고, 돌면 기다린다. 마이그레이션 번호가 겹치면 뒤에 커밋하는 쪽이 번호를 민다.
- 원본 계정은 두 스레드(와 다른 작업자)가 같이 쓴다 — 목록을 열면 필터 · 검색칸부터 확인하고, 원본에 QA 시험 자료를 만들면 바로 지운다.
- 메모리: 대화가 둘이면 Chrome 탭 · 에이전트도 둘씩이다. 95% 넘으면 그 스레드는 에이전트를 띄우지 않고 탭을 바꾼다.

긴 지시문을 매번 치지 않으려고 만든 절차다. 바탕 규칙은 `.claude/skills/qa-agent/SKILL.md`(원본 읽는 법 · 우리 화면에 넣는 법),
자료는 `.claude/skills/ecount-diff/plans/데이터이관/` (`_진행.md` 맨 위 · `_접속.md` 주소/계정 — 비밀번호를 채팅에 옮겨 적지 않는다).

## 역할 — QA → 관리자 → 코더 (기획자는 옆에서 예산)

| 역할 | 누가 | 하는 일 | 왜 이렇게 |
|------|------|---------|-----------|
| QA | 진행자(메인 세션) — **Sonnet**(사용자가 `/model sonnet` 으로 정함) | 원본 loginaa 를 보고 우리 화면에 입력 · 대조, `_진행.md` 에 기록, 코더가 고친 화면을 원본과 더블체크 | 하위 에이전트의 loginaa 이동은 자동 안전 검사가 막는다 — 그래서 QA 는 메인 세션이고, 모델은 세션 모델을 따른다 |
| 관리자 | 에이전트 `model: sonnet`(백그라운드, 필요할 때) | ① `_진행.md` 에 적힌 원본 값과 우리 API(GET 만)를 맞대 **정말 다 · 정확히 들어갔는지** 확인 ② 코더 커밋 검사(흐름 · 검사 다시 돌림, 남의 파일 섞임) ③ `_현황판.md` 진척 · 대기열 갱신 ④ 다음 코더 묶음 지시문 초안 | 진행자 대화를 키우지 않고 검증을 따로 |
| 코더 | 에이전트 `model: opus`(백그라운드) | 관리자가 묶은 차이를 고치고 검사 · 커밋 | 고치기는 어려운 일이라 센 모델로(2026-10-28 사용자 결정: QA · 관리자 Sonnet, 코더 Opus) |
| 기획자 | `node qa/usage-report.mjs` + 진행자 | 회차마다 토큰(진행자 · 에이전트별) · 메모리를 `_현황판.md` 표에 한 줄 | 집계는 스크립트로 — 에이전트를 띄우면 그게 또 토큰이다 |

관리자는 **3회차마다 한 번** 또는 **코더가 끝났을 때** 띄운다(매 회차는 낭비). 관리자 지시문: 이 SKILL.md · `_진행.md` · `_현황판.md` 를 읽고 ①~④, 회사 0005 는 읽기만(GET), 코드는 고치지 않음, `_현황판.md` 만 고쳐 커밋, 보고는 5줄.

코딩 에이전트는 **차이 하나마다 띄우지 않는다** — 화면 · 메뉴 묶음 단위로 모아 넘긴다(매번 파일을 새로 읽는 낭비).
동시에: 화면 에이전트 1~2개(파일이 안 겹치게) + 백엔드 에이전트는 **한 번에 하나**(마이그레이션 번호 · mvn target 충돌).

## 한 바퀴

1. **메모리 확인** (PowerShell `Get-CimInstance Win32_OperatingSystem`).
   - 95% 이상: 새 에이전트를 띄우지 않는다. 진행자 Chrome 탭을 새 탭으로 바꾼다(원본 탭이 오래 열리면 1GB 가까이 먹는다 — `tabs_create_mcp` 후 옛 탭 `tabs_close_mcp`).
   - 사용자 프로그램(ChatGPT · VS Code · 사용자 Chrome 탭)은 닫지 않는다 — 필요하면 사용자에게 부탁한다.
2. **끝난 코딩 에이전트가 있으면 더블체크 먼저**: 보고의 "어디를 열면 무엇이 보이는지" 대로 우리 화면을 열어 원본과 다시 맞댄다.
   `git show --stat <커밋>` 으로 남의 미커밋 파일(router.tsx · EcountLayout.tsx 등)이 통째로 들어가지 않았는지 본다. 어긋나면 같은 에이전트에 `SendMessage` 로 되돌려 보낸다.
3. **전표 하나 고르기**: `_진행.md` 의 '이미 넣은 전표' · 진행표를 보고, 아직 안 해 본 **경우**(전환 · 반품 · 외화 · 로트 · 다중 창고 · 재고조정 · 출하 …)를 고른다.
   원본 자료는 한 달 밀린 11월 날짜(우리는 10월로 넣음). 넣기 전에 우리 API 로 그날 전표부터 본다(`GET /api/<전표>?from=&to=`) — 중복을 넣은 적이 있다.
4. **원본 읽기 → 우리 화면 입력 → 결과 대조**(qa-agent 규칙). 원본 확인에 저장이 필요하면 적요에 `QA` 표시 · 확인 뒤 지운다.
   - Chrome 팁: 숨은 탭 말고 보이는 탭 하나. 여러 동작은 `browser_batch` 로 묶는다. 우리 앱 입력 창에서 **Esc 를 누르지 않는다**(창이 닫혀 입력이 사라짐) — 브라우저 확장 팝업이 뜨면 다른 곳을 클릭.
5. **차이 처리**
   - 한두 줄짜리(조건 하나 · 문구)는 진행자가 바로 고치고 관련 흐름(`qa/flows/*.json`)을 고치기 전 · 후로 돌려 비교한다.
   - 그보다 크면 `_진행.md` 에 적어 두고, 같은 화면 · 메뉴 묶음이 모이면 코딩 에이전트를 띄운다. 지시문에 넣을 것: 원본 실측 내용(칸 · 단추 · 동작) · 고칠 파일 짐작 · 남의 미커밋 파일은 hunk 만 스테이징 · 색/px 금지(토큰) · 검사(`npm run typecheck` · `qa/ui-check.mjs` · `qa/style-check.mjs` · 해당 흐름) · 메모리 빠듯하면 하나씩 · 회사 0005 자료 건드리지 말 것 · 커밋만(푸시 금지) · 보고 형식(고친 파일 · 커밋 · "어디를 열면 무엇이 보이는지").
   - 코딩 에이전트가 고치는 중인 화면은 진행자가 대조하지 않는다(고치는 도중이라 결과가 흔들린다) — 다른 경우로 넘어간다.
6. **기록 · 커밋**: `_진행.md` 에 `루프 N회(날짜): 원본 … → 우리 …, 같음/다른 것 …` 한 줄, '이미 넣은 전표' · 진행표 숫자 갱신. `_진행.md` 만(또는 진행자가 고친 파일과 함께) 커밋. `_접속.md` 는 gitignore — 넣지 않는다.
7. **기획자**: `node qa/usage-report.mjs` → `_현황판.md` 기획자 표에 한 줄(진행자 · 에이전트 토큰, 메모리). 3회차마다 또는 코더가 끝났으면 **관리자**를 띄운다.
8. **사용자에게 한 줄** — `node qa/migrate-progress.mjs` (진행자의 프로젝트 진척판: 기초자료 · 전표 · 경우 % · 남은 시간) 를 돌려 숫자를 그대로 쓴다. 해 본 경우는 `_현황판.md` 체크리스트를 [x] 로: 이번 회차 결과 + 남은 원본 10월 전표 수(진행표 '원본 건수 − 넣은 건수' 합) + 남은 '안 해 본 경우' 수 + 돌고 있는 에이전트.
9. `/loop` 로 부른 경우: 대기 없이 다음 회차로(`ScheduleWakeup` 60초). 에이전트 알림이 오면 2번부터.

## 멈출 때

`_진행.md` 맨 위 '다시 시작할 곳' 에 마지막 회차 · 돌던 에이전트와 그 일 · 다음에 볼 것을 적는다.
원본 세션 주소가 만료되면(로그인 화면) 사용자에게 새 주소를 받아 `_접속.md` 에 적는다.
