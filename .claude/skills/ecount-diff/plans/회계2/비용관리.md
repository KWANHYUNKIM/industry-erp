## 2. 비용내역입력 (E060812)

- 머리: `작성일자`(연 ▾ / 월 ▾ / 일 칸 — 오늘 2026/10/20) · `비용그룹`(코드도움) · `결제구분`(○개인비용 **◉회사비용**) · `출금계좌`(코드도움) · `비고`.
- 격자 위: `찾기(F3)` · `보류` · `카드매입내역`.
- 격자 열: `사용일자 · 비용코드 · 비용명 · 사원 · 거래처코드 · 거래처명 · 사용금액 · 적요 · 부서 · 프로젝트 · 배부액 · 금액1 · 금액2 · 적요1 · 적요2 · 적요3`. 처음 3줄, 빈 사용일자 `====/==/`.
- 합계줄: 사용금액 · 금액1 · 금액2 열에 합(처음 0).
- 줄 입력: 사용일자 칸에 일(20)만 넣으면 `2026/10/20`. 비용코드 Q2E1+Enter → 비용명 자동. 사원 칸 '0'+Enter → `사원검색` 창(사원코드 · 사원명, 23명) → 고르면 이름.
  Enter 로 오른쪽 칸 이동. 적요 다음 Enter 는 부서 칸으로 가며 부서검색 창이 뜬다.
- 아래 단추: `저장(F8)` · `저장/전표(F7)` · `다시 작성` · `리스트`.
- **검증**: 사원 빈칸으로 저장 → 사원 칸 빨간 테두리(글 없음). 저장 안 됨.
- **비용통제(한도) 검사**: 저장하면 알림 `한도금액이 초과되었습니다. 전표를 저장하겠습니까?` / `[취소] 클릭 시 내역을 확인할 수 있습니다.` [확인][취소].
  [취소] → 창 `비용통제`: `한도금액이 초과되었습니다.` `다음 사항을 확인 바랍니다.` `1.비용` `사용인원 체크` 표 `비용코드 · 비용명 · 사용인원 · 사용자` = `Q2E1 · QA회계2-교통비 · (빈칸) · 고준희` · [닫기].
  → 금액(30,000)이 한도(50,000) 안이어도, **인원통제 '사용' 인데 사용인원에 그 사원이 없으면** 초과로 본다. 통제알림방식 '경고 및 알림' 이라 [확인] 으로 저장된다('저장불가' 면 막힐 것 — 못 잼).
- 저장 뒤: 안내 글 없이 입력 판이 비워진다(새 전표). 번호 `2026/10/20 -1`(일자-No.).
- `저장/전표(F7)` = 저장 + **비용전표 인쇄 창**(제목 '비용전표', 작성자 · 전표번호 · 표 `비용명 · 거래처명 · 사용금액 · 적요` · 총합계 · 합 계 · 출력 시각 · [인쇄][Excel][닫기]). 회계전표를 만들지 않는다.

## 3. 비용내역조회 (E060813)

- 열: `전표번호 · 비용그룹명 · 비용명 · 사용자 · 사용금액 · 회계반영여부 · 인쇄`(머리 높이 51.5 — 정렬 표시 두 줄). 버튼 `신규(F2)` · `인쇄` · `선택삭제`.
- 줄: `1 | 2026/10/20 -1 |  | QA회계2-교통비 | 고준희 | 30,000 |  | 인쇄`(머리에 비용그룹을 안 고르면 비용그룹명 빈칸).
- 전표번호 링크 → 창 `비용내역수정`(입력과 같은 판 + 번호 '- 1'). 단추 `저장(F8)` · `저장/전표(F7)` · `복사` · `삭제` · `닫기` · `보내기` · `H`.
- 수정: 사용금액 30,000 → 40,000 저장(한도 알림 다시 뜸 → 확인) → 목록 40,000.
- 결제구분 회사비용 → 개인비용 으로 수정 저장 가능.
- 회계반영(가지급금정산서) 뒤 수정 창: 머리에 `가지급금정산서` 꼬리표가 붙고 `출금계좌` 칸이 없어진다. 목록 [회계반영여부] 는 여전히 빈칸이었다(원본 그대로 적음).
- 삭제: 수정 창 [삭제] → 알림 `전표를 삭제하겠습니까?` `- 비용내역입력` [확인][취소] → 목록 '등록된 데이터가 없습니다.'
  **회계반영된 전표도 지워지고, 그 가지급금정산서(회계전표)도 같이 사라진다**(회계거래조회에서 26/10/20-24 없어짐).

## 8. 고칠 순서 (다시 하기)

1. 스키마 한 번에(`bash qa/next-migration.sh` 로 번호, db/migration · db/tenant 둘 다): `expense_control_types`(code · name · period_type · person_control · limit_type · notice_type · remark · use_yn),
   `expense_items`(code · name · account_id · control_type_id · limit_amount · remark · use_yn, 사용인원 `expense_item_users`),
   `expense_groups`(code · name · control_type_id · add_input · remark · use_yn, `expense_group_items`), 기존 `expenses` 에 `expense_item_id` · `employee_id` · `pay_type` 기본 COMPANY · `settled_journal_id`.
   기존 `expenses` 자료는 계정 → 비용 마스터로 옮길 수 없으니 expense_item_id nullable.
2. 마스터 세 화면(1.1~1.3) + 메뉴 · 라우트 · 권한(MenuPermissionCatalog) — 공용 파일은 바로 커밋.
3. 비용내역입력을 머리+줄로. 저장 때 분개 없애기(6) — 이건 다른 화면(손익 · 프로젝트 손익)이 지출 분개를 읽고 있는지 먼저 grep.
4. 전표별회계반영(비용) → 가지급금정산서 분개(차 비용 마스터의 계정 / 대 가지급금, 거래처 = 사원) · 삭제 시 함께 삭제.
5. 비용통제 알림 · 비용일괄등록 · 인쇄 창.
6. 흐름 시험 `qa/flows/expense-flow.json`: 위 6장 표 숫자 그대로.

**고른 방법(2026-10-20 다시 하기 1바퀴):** 새 비용내역 엔티티를 따로 두지 않고 `expenses` 에 `expense_item_id` · `employee_id` · `expense_group_id` · `settled_journal_id` 를 더하고(V413 · 테넌트 V285), **비용코드가 있는 줄만 저장 때 분개를 건너뛰게** 한다 — 프로젝트 손익(ProjectProfitService) · 부가세 요약(AccountingService) · 수입(IncomeService) · 결재 연결(ApprovalService)이 모두 `expenses` 를 바로 읽고, qa.mjs 의 지출 단언 다섯 곳(scenarioExpenseJournal · ExpenseDocNo · PartnerLink · 프로젝트 손익 · 사용중지 계정)과 flows(expense · expense-list · expense-pay-type · cash-book)는 계정만 주는 옛 요청이라 그대로 즉시 분개로 통과한다. 표를 둘로 가르면 비용내역조회 · 현황이 두 곳을 합쳐야 한다.
