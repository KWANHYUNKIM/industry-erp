## 고칠 때 검증 절차 (CLAUDE.md 10.1)

앱이 떠 있어야 한다(백엔드 8081 · 프론트 5180). 묶음 하나씩, 커밋 하나씩.

```bash
node qa/style-snapshot.mjs save /tmp/before-<묶음>        # 고치기 전 — 화면마다 계산된 스타일
#   … 공용 부품 하나 고침 …
node qa/style-snapshot.mjs save /tmp/after-<묶음>
node qa/style-snapshot.mjs diff /tmp/before-<묶음> /tmp/after-<묶음>
```

- **바뀌어야 할 것만 바뀌었는지** 본다: 바뀐 속성이 그 묶음이 노린 것(높이 · 여백 · 테두리)뿐이어야 한다. 엉뚱한 화면의 색 · 폭이 바뀌면 멈춘다.
- **잠금**: `/tmp/before` 를 잡는 동안 다른 작업자의 재기동이 끼면 로그인 화면이 찍힌다(공용.md 2026-10-14 기록). 스냅숏 앞뒤로 같은 HEAD · 같은 백엔드 기동인지 확인하고, 실패로 센 화면은 다시 뜬다. 여러 작업자가 같은 공용 CSS 를 동시에 고치지 않도록 묶음마다 이 문서 표에 '고치는 중(이름 · 시각)' 을 적고 시작한다.
- 묶음별 원본 대조 1화면 이상: getComputedStyle 로 원본 값 = 우리 값을 적는다(아래 각 묶음의 '대조 화면').
- 그다음 `bash qa/precommit.sh`(typecheck · test:unit · ui-check · dto-check · arch-check · style-check). style-check 래칫이 줄면 `node qa/style-check.mjs --update`.
- 입력 화면을 바꾼 묶음(A · C)은 `qa/flows/` 의 해당 흐름(cash-withdraw-journal.json · vat-slip-book.json · tax-voucher-crud.json · daily-worker.json …)을 `node qa/shot.mjs` 로 돌린다 — '빈 저장 → 빨간 테두리' 단계의 기대 글자가 바뀐다.
- 휴대폰 폭: `node qa/mobile-check.mjs` (C 는 `.ec-form` 의 768 이하 규칙 1176~1184 줄이 이름표 93 을 따로 둔다 — 같이 본다).
