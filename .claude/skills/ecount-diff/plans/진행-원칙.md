# 진행 원칙 — 사용자가 다시 말하지 않아도 늘 지킨다 (2026-10-21 20시 사용자 지시)

## 목표
- **이카운트 원본과 무조건 똑같이** 만들어 프로젝트를 끝낸다. 기능 · 흐름 숫자 · 글자 · 꼴 전부. 다르면 원본이 맞다.
- **주간 사용량 20~30% 안에서** 끝낸다(2026-10-21 시작 때 59% 남음). **빠르게** 한다.
- 둘이 부딪치면: 같게 만드는 것 > 토큰 > 속도. 같지 않은 채 '끝' 으로 치지 않는다.

## 진행자(메인 세션)
- 큰 문서를 읽지 않는다. 다음 차례는 `plans/재개.md` 맨 위 절 + `마무리-묶음.md` 맨 앞 칸 + `완료.md` 만 grep 으로 본다.
- 일은 작업자에게 맡기고, 지시문에 **할 일 · plans 줄 번호 · 확인 방법**을 다 적는다(작업자가 찾아 읽지 않게).
- 작업자 보고는 받은 그대로 사용자에게 2~3줄로. 표 · 과정 설명 없음.
- 작업자 하나가 끝나면 **바로** 다음 묶음을 넣는다(사용자에게 묻지 않는다 — 사용자 결정 대기 항목만 건너뛴다).
- 로그인 만료(`LOGIN_EXPIRED`)면 원본 작업자만 멈추고 사용자에게 새 `ec_req_sid` 주소를 받는다. 코드 작업자는 계속.

## 속도
- 동시에: **원본 브라우저 작업자 1명 + 코드 작업자 3명**(맥 8GB — 빈 메모리 1GB 아래면 코드 작업자를 2명으로).
- 무거운 명령(typecheck · mvnw · shot · precommit)은 `/tmp/erp-heavy.lock` 로 줄 세운다 — 작업자를 늘려도 이것 때문에 서버가 안 죽는다.
- 원본 작업자는 **모듈 하나의 '원본 재기 필요' 를 몰아서** 한 바퀴에 잰다(묶음마다 원본을 따로 열지 않는다).
- 코드 작업자는 plans 에 적힌 원본 실측으로 바로 고치고, 값이 없으면 지어내지 않고 '원본 재기 필요' 로 남긴다 → 원본 작업자 몫.
- 백엔드 재기동은 `qa/restart-backend.sh` 만(이미 반영된 HEAD 면 스스로 건너뜀).

## 토큰
- 코드만 묶음 = `model: sonnet`. 원본을 여는 작업자만 기본 모델.
- 작업자는 `plans/작업자-요약.md` 의 '토큰 아끼기' 를 지킨다: 출력 자르기 · 파일 통째 읽기 금지 · 스크린샷 0~1장 · 보고 SUMMARY 3줄.
- 같은 일을 두 번 하지 않는다 — 시작 전에 `완료.md` grep, 끝나면 한 줄 더한다.

## 낭비 줄이기 (2026-10-21 20:18 사용자 — "낭비를 최소화")
- **재고 나서 고친다.** 원본 값이 없는 항목은 코드 작업자가 짐작으로 먼저 만들지 않는다 — 원본 작업자가 모듈 단위로 몰아 재서 plans 에 적은 뒤 코드 작업자가 한 번에 고친다(짐작 → 원본 대조 → 다시 고치기 두 바퀴를 없앤다).
- **아는 오류는 다시 캐지 않는다.** 남의 파일 타입체크 · style-check 실패는 지시문에 '알려진 실패' 로 적어 주고, 작업자는 자기 파일만 본다.
- **받은 일은 끝낸다.** 크다고 판단만 하고 손 안 대고 돌아오지 않는다(지시문을 읽은 토큰이 버려진다). 정말 못 하면 첫 5분 안에 이유를 보고.
- **작업자는 한 바퀴(묶음 하나)만 쓰고 새로 띄운다.** 이어 붙이면(SendMessage) 맥락이 40만~78만 토큰까지 커져 매 단계 그만큼 캐시를 다시 읽는다 — 2026-10-21 밤 4시간 $175 중 대부분이 이것(캐시 읽기 9.5억). 넘길 것은 plans 기록과 지시문으로.
- 모델: Sonnet 기본. Opus 는 Sonnet 이 같은 일에서 한 번 실패한 것만.
- 진행자 보고는 2줄. 알림마다 길게 쓰지 않는다.
