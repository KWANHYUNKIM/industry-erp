우리 ERP(localhost:5180, 회사 0001 admin)에서 같은 것을 눌러 **같은 창이 같은 모양으로** 뜨는지 견준다. 다르면 여기에 적고 코더가 고친다.
UI/UX 가 깨진 것(겹침 · 넘침 · 정렬 · 부품 모양 · 접힘/펼침)도 같이 적고 고친다.

## 규칙

- 원본은 **운영 중인 회사**다. 저장 · 삭제 · 전송 · 승인 · 설정 저장 · 권한요청 · 쪽지/메일 열기 같은 **되돌릴 수 없는 클릭은 하지 않는다**.
  창을 여는 데까지만 하고 [닫기] · Esc 로 닫는다. 권한 없음 · 메뉴 없음은 적고 넘어간다.
- 원본 주소: 사용자가 준 세션 주소(`ec_req_sid`)를 쓴다. 로그아웃되면 멈추고 '다시 시작할 곳'에 적는다(사용자에게 새 주소를 받는다).
- 작업자: QA(Sonnet)는 한 번에 **한 묶음**. 코더는 QA 가 찾은 차이 하나 ~ 몇 개를 한 화면 단위로. 같은 화면 · 파일을 두 작업자가 동시에 잡지 않는다.
- 메모리 상한 90%(8GB 기계 — 작업자 동시 2명까지). 무거운 것(typecheck · 헤드리스 Chrome · mvn)은 `/tmp/erp-heavy.lock` 으로 줄 세운다.
- 고칠 때: CLAUDE.md 10.1 · 10.2(토큰 · 부품 클래스 · 인라인 색/px 금지 · style-check 래칫), 고친 화면마다 `qa/flows/` 흐름 하나, `npm run typecheck` ·
  `node qa/style-check.mjs` · `node qa/ui-check.mjs`(지금 실패 2건 — 버튼 예외 379 · 고른 줄 버튼 84 — 은 이 일 전부터 있던 것, 늘리지만 않으면 된다).
  커밋은 고친 파일만 pathspec 으로(`git commit -- <파일들>`), 그다음 `git pull --rebase && git push`.
- 이미 알려진 결정 필요 항목(버튼 치수 loginad 28/24·둥글기 5 vs 우리 26·10, 입력 표 머리 정렬, [Fn], 행번호 상자, 조회기간 표시)은
  `../디자인-점검-20261031.md` — **사용자 결정 전에는 고치지 않는다.**
