# 원본 업무권한 — 막는 방식 (2026-10-30 loginaa 실측 + 원본 도움말)

데모 계정(사용자 ecount)은 사용자관리 4화면(사용자등록 C000114 · 권한그룹 설정 · 권한승인대기현황 · 관리자설정 E000131)과
결재설정(E070109)이 **업무 권한 없음** 이라 설정 화면 자체는 못 열었다. 아래는 막힌 화면의 실제 모습과 원본 도움말(온라인 매뉴얼) 내용.

## 1. 막힌 화면 (메뉴 진입 권한 없음)
본문 틀 가운데:
- 회색 자물쇠 그림(큰 아이콘)
- `(결재설정) 업무 권한이 없습니다.` — 괄호 안 업무(메뉴)이름은 파란 글자, 뒤는 검정
- `서비스를 이용하려면 회사 마스터에게 문의 바랍니다.`
- `우리회사마스터 : ecount , sykim , 이카운트` — 마스터 사용자들(파란 글자, 쉼표 구분), 큰 글씨
- 파란 [권한요청] 단추(결재설정 화면에는 있음, 사용자관리 › 사용자등록에는 **없음** — 마스터 전용 메뉴는 요청 불가로 보임)
- 왼쪽 메뉴 · 위 메뉴는 그대로 보이고 그 메뉴가 켜져 있다. 창 제목(탭 이름)은 '권한없음'.
- 도움말 영상 속 다른 예: `(판매) 업무 권한이 없습니다. 서비스를 이용하려면 회사 마스터에게 문의 바랍니다. (접근)` — 판매 업무 안의 판매조회 · 판매입력 … 어느 메뉴든 같은 업무면 '(판매)' 로 막힌다.
- [권한요청] → 마스터에게 요청이 가고 Self-Customizing › 사용자관리 › **권한승인대기현황** 에 쌓이는 것으로 보임(누르지 않음 — 실제 요청이 나감).

## 2. 행위(입력 · 수정 · 삭제) 권한 없음
게시판 View 에서 [수정] → 알림 창:
```
권한이 없습니다.
마스터에게 문의 바랍니다.
- 🚗 1. 차량 정보관리 게시글권한 (수정(작성))
```
(알림 머리 '알림', [확인]) — 형식: `- {메뉴/게시판 이름} {권한 이름} ({행위})`.

## 3. 권한 모델 (원본 도움말 '사용자 ID별 업무 권한 설정 방법' · '업무권한 예외설정 기준')
- 사용자 ID 마다: Self-Customizing › 사용자관리 › 사용자등록 › ID 클릭 › [권한] 탭 › **기본권한**
  - `업무모든권한` (권한있음을 줄 메뉴가 많을 때) / `업무권한없음` (권한없음을 줄 메뉴가 많을 때) / **권한그룹** 선택
- 업무권한 [설정] → **개별권한설정** 창: 업무(판매 · 구매 · 결재설정 …)마다 아래 넷 중 하나
  | 권한있음 | 입력화면 · 출력물에서 입력/조회/수정/삭제 모두 가능 |
  | 권한없음 | 모두 불가능 (진입 시 1번 자물쇠 화면) |
  | 예외(행위) | 조회 외 입력/수정/삭제 등 세부 권한을 따로 — 모두 권한없음이면 '조회'만 |
  | 예외(메뉴) | 업무 안의 하위 메뉴(판매입력 · 판매현황 …)마다 진입 권한 |
  - 기본권한과 다르게 할 업무만 체크하면 된다. **예외 설정은 업무별 권한보다 항상 우선.**
- **권한그룹 설정**: [신규] → 권한코드 · 권한명 저장 → 그룹 오른쪽 업무권한 [설정] 에서 업무별로 같은 4가지 → 사용자등록 [권한] 탭 기본권한에서 그룹 선택.
- [권한복사]: 한 ID 의 권한을 다른 ID 들로 복사.
- 마스터 ID(관리자설정)는 모든 권한, 다른 사용자의 권한을 정한다. 마스터는 여러 명(데모: ecount · sykim · 이카운트).
- 그 밖에 도움말 제목으로 확인된 것: 사용자 ID별로 특정 전표만 보기, '사용메뉴만' 설정, 일반 사용자가 기안서통합관리를 못 보게, 다른 사람이 품목 등록 · 수정 못 하게, 사용자 ID별로 조회 양식 다르게, 부서별 권한.
- 게시판은 따로 **게시글권한**(조회 · 수정(작성) …)이 있다(2번 알림).
