## 합치는 순서 (권장)

1. 회사 PC 덤프를 맥으로 옮긴다(본인만 보는 클라우드 · USB — 공개 저장소 금지, backups/ 는 gitignore).
2. 맥에서 **되살리기 전에** 맥 DB 를 먼저 뜬다: `bash qa/db-dump.sh` (맥 쪽 수당 · 공제 · 근태 · 휴가 값을 잃지 않게).
3. 맥에서 그 항목들의 값을 적어 둔다 — 화면(관리 › 수당항목등록 · 공제항목등록 · 근태항목등록 · 휴가항목등록) 또는 GET API 로 코드 · 이름 · 설정.
4. `bash qa/db-restore.sh backups/erp-20261029-1756.dump` 로 회사 PC 자료를 되살린다.
5. 3 에서 적은 항목 중 회사 PC 에 없는 것만 **화면으로** 넣는다(회사 0005 는 API · DB 직접 쓰기 금지 — QA 대상).
   회사 PC 에 이미 있는 것: 수당 = 식대 · 연장근로 · 직책 · 차량유지비 등 7 · 공제 = 노조회비 · 소득세(51) · 주민세(52) 등 4 · 근태 = 연장근무 · 주말근무 · 예비군 · 2026연차 · 휴가 = 2026연차(20001).
   남은 원본 항목: 수당 연차 · 출산보육 · 부양가족 · 상여 / 공제 건강보험 · 고용보험 · 연말정산 · 사우회비 · 장기요양 / 근태 경조사휴가 · 2025연차 · 2022~2024연차 / 휴가 6.
6. `node qa/migrate-progress.mjs` 로 숫자 확인 → `_진행-B.md` 관리 줄 갱신.

## 주의

- 덤프 되살리기는 그 PC 의 DB 를 통째로 바꾼다. 2 번을 빼먹으면 맥 자료가 사라진다(10-27 baseline 사고 참고: 메모리 flyway-baseline-data-loss).
- 마이그레이션 번호: 회사 PC 는 V510 / 테넌트 V382 까지. 맥에서 새 마이그레이션을 만들었으면 번호가 겹치는지 먼저 본다(메모리 github-push-account).
- 소득자 4명(세무)은 주민번호가 있어야 넣는다 — 사용자 결정 대기.
