## 0. 권한요청 단추 (사용자 보고 10-30 "권한요청 버튼 … 깨지는데?")

**왜 깨졌나**: 자물쇠 화면 CSS 묶음(`.ec-noperm*` · 권한승인 · 관리자설정 칩 · 권한요청 알림창)을 `shell.css` 끝에 붙일 때(6b04c524)
휴대폰 `@media (max-width: 768px) { … }` 의 닫는 괄호 **안쪽**에 들어가, PC 에서는 하나도 안 먹었다. 그래서 [권한요청] 은 맨 `.ec-btn`
(flex · 왼쪽 정렬)로 그려져 글이 단추 왼쪽에 붙고, 자물쇠 그림은 크기 · 색 없이 그려졌다. 괄호를 제자리로 옮기고(작업 트리에 이미 누가 옮겨 둔 것을 같이 커밋), 모양을 원본에 맞췄다.

**원본 근거**: loginaa 는 이 작업자가 로그인할 수 없어(비밀번호 입력 금지) getComputedStyle 을 못 쟀다 — 대신 영상 2000(2023-08, 1280px 녹화 · 100%)
프레임을 픽셀로 쟀다(`cv2`, 13초 프레임). 1998(빨강 테마) · 1514(2022 초록 — 그땐 단추가 아니라 굵은 글자 링크)도 같은 자리 · 같은 배치.
`click-orig-E070109.txt`(결재설정 실측): [권한요청] → '권한요청사유' 창 · [확인] [닫기]. 원본에서 요청은 보내지 않았다.

| **권한그룹 승인 효과** | 요청자가 속한 그룹 자체를 바꿔 요청자에게 권한이 생긴다 | 그룹은 바꾸지만 요청자에게 **개별 '권한없음' 줄이 있으면 그 줄이 이겨 여전히 막혔다**(승인으로 표시되는데 안 열림 — API 로 재현: 승인 뒤 `/me/permissions` SALES DENY). 기본권한이 업무권한없음/업무모든권한인 사람도 그룹 승인이 눌렸다(그룹을 바꿔도 닿지 않음) | **틀림 → 고침**: 그룹 승인은 그 업무의 개별 줄을 지워 그룹을 따르게 하고, 기본권한이 권한그룹이 아니면 서버 400 · 화면 [권한그룹] 잠금. group-approve 흐름 |
| 반려 | [반려] → 반려, 요청자는 계속 막힘 | 같음 | 같음 — request 흐름 |
| 결과 알림 | 요청자 · 승인자 모두 메신저로 결과 | 1:1 방에 `[권한요청 승인] (업무) …` / `반려` | 같음(글은 미실측) |
| 기간 · 만료 | 영상 · 도움말 어디에도 승인 기간 · 만료 없음 | 없음 | 같음 |

## 6. 권한그룹 · 권한복사 · 관리자설정

## 7. 업무권한 밖(다른 권한 — 이번 범위 아님, 빠짐)
양식권한 · 확인권한(확인 절차) · 허용권한(품목 · 거래처 · 창고 · 부서) · 기타권한(권한 적용 범위 '본인 전표만', 단가 · 금액 수정) · 게시글권한 · 위젯승인. 도움말이 '권한 별 비교' 로 따로 다루는 것들이다.

## 8. 곁다리로 고친 것
- 사용중지한 아이디로 로그인하면 `서버 오류가 발생했습니다: User is disabled`(500)가 새었다 → 401 `사용이 중지된 아이디입니다. / 마스터에게 문의 바랍니다.`(원본 문구 미실측). group-approve 흐름.
- `work-permission-request.json` 이 '요청자 — 승인 뒤' 단계에서 판매조회 2천여 건 로딩을 기다리다 끊긴 적이 있다(브라우저로는 열림 — 흐름 시간 문제).
