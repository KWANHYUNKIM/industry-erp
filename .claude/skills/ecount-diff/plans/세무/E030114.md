# 중도정산등록/수정 (E030114) · 중도정산 PDF 다운로드 (E030118) — 정리 단계 (2026-10-13)

세무 › 원천징수 › 퇴직정산. **우리에게 없는 화면이다**(라우트 · 메뉴 · 서버 모두 없음 — 퇴사자리스트 `/hr/retired` 의
'중도정산원천징수연월' 열만 늘 빈칸으로 있다). 원천징수이행상황신고서 A02(중도퇴사) 줄도 `WithholdingService` 416 줄에서 `null`(빈칸).

원본은 SKILL 2장 1번(탭 지정 입력)으로 쟀다. computer 클릭은 쓰지 않았다(스크린샷만).
입력 창(정산공제항목 입력)은 **연말정산 › 정산내역등록/수정(E030109)** 과 같은 서식이다 — 다음 묶음 '연말정산' 과 같이 만든다.

## 2. [대상자추가] → `중도정산 대상자 추가` 창

- 머리 `중도정산 대상자 추가` · 오른쪽 `검색어 [Enter]` · `Search(F3)`. 열: (체크) · 사번 · 성명 · 주민번호 · 퇴사일(YYYY.MM.DD). 아래 `적용(F8)` · `닫기` · `키보드 활용 TIP`.
- 나오는 사람: **퇴사자리스트에 퇴직처리된 사람 중 귀속연도에 퇴사한, 아직 중도정산 목록에 없는 사람**. 처음엔 빈 목록(`등록된 데이터가 없습니다.`) — 00007 을 퇴직처리하자 나왔다.
- **주민번호가 없으면 빨간 글 `주민번호오류` 이고 체크칸이 잠긴다**(`disabled`) — 고를 수 없다. 사원등록에 주민번호를 넣자 풀렸다.
- 안 고르고 [적용(F8)] → `등록할 사원이 선택되지 않았습니다.` [확인]
- 고르고 [적용] → 안내 없이 창이 닫히고 목록에 줄이 생긴다(원천징수연월 빈칸).

## 6. 우리와 다른 점 · 고칠 순서 (다시 하기 단계)

1. **화면이 없다** — `/accounting/withholding/mid-settlement`(가칭) 목록 + 메뉴 '퇴직정산' 의 퇴직금계산 다음 · 권한. 서버 자리는 퇴직금계산(`accounting/retirementpay/`)이 사원 · 급여를 읽는 길을 그대로 따른다 — CLAUDE.md 4.1 표에 accounting → hr 은 없고(KNOWN 부채), hr → accounting 만 허용이니 새 간선을 늘리지 않게 다시 하기 단계에서 먼저 정한다.
