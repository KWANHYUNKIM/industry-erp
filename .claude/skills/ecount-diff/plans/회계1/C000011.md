## 3. 우리와 다른 점 (8)

1. **회계거래조회 적요** — 원본은 적요를 비우면 빈칸, 우리는 `fillVatSlip` 이 거래처명으로 채운다(`desc = … : partner.getName()` → `e.setDescription`). 줄 적요는 원본 전표 인쇄가 거래처명을 찍으니 줄은 그대로 두고 **전표 description 만 빈칸**이어야 한다.
2. **매입/매출장 일자-No.** — 원본은 그날 부가세 전표 일련(-1 · -2), 우리는 `dateNo(r.date, r.no)` 로 회계 docNo(-12 · -13).
3. **매입/매출장 세부내역** — 원본은 [세부내역] 품명 요약(`품명 외 n건`, 없으면 빈칸), 우리는 `text: e.description`(적요 · 거래처명).
4. **매입/매출장 매입/매출 판** — 원본은 한 표 9열(매입공급가액 · 매입부가세 · 매출공급가액 · 매출부가세, 계 · 누계 건수는 합친 수), 우리는 매출표 · 매입표를 따로 둘(VatBookPage 주석에도 '못 쟀다'로 남아 있음 — 이번에 잼).
5. **빈 저장 검증** — 원본은 알림 없이 거래처 칸 빨간 테두리 + 말풍선, 우리는 판 위 `ec-alert` 글줄 `거래처: 자료를 입력 바랍니다.`. 말풍선 글자는 못 잼.
6. **[저장/전표(F7)]** — 우리는 저장 뒤 `/accounting/journals?entryId=` 로 분개를 연다, 원본(수정 창)은 회계거래조회로 돌아왔다(분개 판은 못 봄 — 새 창 여부 다시 볼 것).
7. **[매출전표II로 변경] · [매입전표II로 변경] · [웹자료올리기]** — 우리에게 없음(II 화면이 없다).
8. **매입/매출장 조건 라디오** — 원본은 라디오를 누르면 곧바로 조회(우리는 [검색] 을 눌러야 하는지 다시 하기에서 볼 것).

같은 것: 칸 차례 · 기본 계정 · 자동 부가세 10% · 저장 뒤 빈 화면 · 수정 창 일자 막힘과 `- 일련` · 수정 저장 뒤 목록 · 삭제 문구 둘 · 분개 계정과 차대 · 수정 · 삭제 뒤 시산표 되돌림 · 유형명 `세금계산서` · 전자구분 `전자-신`.

## 4. 고칠 차례(다시 하기)

1. ① 서버 description 빈칸(줄 적요는 거래처명 유지) — `fillVatSlip` 한 줄 + `VatSlipPage` 수정 창 적요 되살리기(`e.description !== e.partnerName` 조건 정리). 다른 화면(전표 인쇄 · 계정별원장 적요)이 description 을 쓰는지 먼저 grep.
2. ③ 세부내역 = `vatDetail.items` 첫 품명 + ` 외 n건`(없으면 빈칸) — VatBookPage `text`.
3. ② 장부 일련 — 같은 날 부가세 전표(매출 · 매입 · 판매 회계반영 · 세금계산서 전표)를 입력 차례(id)로 1부터. 화면에서 셈할 수 있다(서버 변경 없음). 원본이 날짜별로 재매기는지 · 지운 뒤 당겨지는지는 다시 하기에서 한 번 더 확인.
4. ④ 매입/매출 판 한 표 9열.
5. ⑤ 빈 저장: 칸 빨간 테두리 · 말풍선(공용 부품에 같은 꼴이 있으면 그것) — 원본 말풍선 글자부터 잰다(잠금 + 스크린샷, 칸에 포커스).
6. 우리 쪽 같은 QA 전표로 흐름 대조: 매출 10,000 → 회계거래조회 → 시산표(108 · 255 · 404) → 20,000 → 매입 → 매입/매출장 → 삭제 뒤 되돌림. `qa/flows/` 에 흐름 하나.
7. ⑥ ⑦ 은 원본에서 다시 본 뒤(II 화면은 묶음 밖).
