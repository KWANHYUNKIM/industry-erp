## 우리 쪽(지금)

- `/accounting/accounts` `AccountsPage.tsx` 제목 '계정과목등록', 메뉴 이름도 '계정과목등록'(원본 `계정등록`), 메뉴 차례가 거래처등록 바로 뒤(원본은 사원(담당)등록 뒤).
- 평평한 45계정, 코드 **3자리**(108 외상매출금 · 135 부가세대급금 · 253 미지급금 — 분개 코드가 서비스에 박혀 있다: `JournalService` 의 addDebit(e, "135", …)).
- 열: 번호 · 계정코드 · 계정과목명 · 구분(자산 · 부채 · 자본 · 수익 · 비용, 색 글자) · 세부분류 · 사용(누르면 토글). 조건은 구분 알약뿐. 수정 · 삭제 없음.
- `accounts`: code · name · division(ASSET/LIABILITY/EQUITY/REVENUE/EXPENSE) · detail_category · active · evidence_report.

## 다른 점

1. 계정 나무(상위계정 · 묶음 줄 · 추가 링크) — 우리는 평평하고 세부분류 글자만.
2. 대차구분 · 평가구분 · 수입지출구분 · 거래처별집계구분 · 관련업무 · 추가항목유형 · 적요1 · 2 — 우리 없음.
3. 계정종류: 원본 자산 · 부채 · 자본 · 손익 · 원가(1~3), 우리 자산 · 부채 · 자본 · 수익 · 비용.
4. 코드 체계 4자리 vs 3자리 — 바꾸면 서비스의 박힌 코드 · 모든 전표가 따라와야 한다(바꾸지 말고 표시 · 새 계정만 원본 꼴로 할지 사용자 결정).
5. 열 · 조건 · 하단 버튼 · 등록 창이 다 다르다. 수정(코드 눌러 수정 창) · 사용중단/삭제 · 적요 등록이 없다.

## 고칠 차례(다시 하기)

1. 화면만 먼저(스키마 그대로): 제목 '계정리스트' · 메뉴 `계정등록` 을 사이트맵 자리로, 열 `[계정코드]계정명 · 대차구분(자산 · 비용 → 차변, 나머지 대변) · 계정종류 · 사용구분 Yes/No`,
   조건 계정코드 · 계정명 · 대차구분 · 계정종류 · 사용구분(기본 사용), 하단 신규(F2) · 사용중단/재사용 ▲, 코드 눌러 '계정수정'. CRUD 는 QA회계1- 새 계정으로.
2. 백엔드(V… 본사 + tenant): `accounts.parent_id`(나무) · `debit_credit` · `eval_kind` · `cash_flow_kind` · `partner_aggregate` · `related_work` · `remark1/2`. 기존 45계정 백필(대손충당금 · 감가상각누계액 = 대변 · 평가계정).
