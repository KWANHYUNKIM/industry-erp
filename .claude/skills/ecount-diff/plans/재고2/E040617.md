  격자 `시리얼/로트No. | 품목명[규격] | 규격 | 입고일 | 유효기한 | 입고수량 | 현재고 | 창고 | 상태 | 상세내역 | 처리(출고 · 실사 · 보류/해제)`. 상세내역은 줄 아래 펼침(일자 · 구분 · 수량 · 잔량 · 적요).
  등록 창 `시리얼/로트No. 등록`: 로트No.* · 품목* · 창고 · 입고일 · 유효기한 · **입고수량*** · [등록].
- 엔티티 `inventory/lot/Lot.java`(표 `lots`): lot_no(unique 50) · item · warehouse · inbound_date(NOT NULL) · expire_date · inbound_qty(NOT NULL) · stock_qty(NOT NULL) · held.
  **사용구분(사용중단) · udi코드 · 부가정보 칸이 없다.** 상태는 `LotStatus.of(held, stockQty)` 파생.
- `LotService.create` — 입고수량 필수(>0), 그 수량으로 stock_qty 를 채우고 **INBOUND 내역 한 줄**(적요 '로트 입고 …')을 만든다. 원본 등록은 내역 0줄.
- `consume`(출고) · `hold`(보류) · `adjust`(실사) — 목록 줄 버튼. 원본 등록 화면에는 이런 처리가 없다:
  실사 = 원본 `시리얼/로트No.재고조정`(E040634, 우리 `/quality/lot-adjust` 가 이미 같은 `adjust` 를 씀), 출고 = 원본 내역입력 '판매' 등(우리 `/quality/lot-tx-list` 내역입력 있음),
  보류 = 원본에 없음(가장 가까운 것이 마스터 **사용중단**).
- 잔량 판은 원본 `시리얼/로트No.재고현황`(E040619) 몫이고 **우리 `/quality/lot-stock`(LotStockStatusPage) 이 이미 있다** — 재고 판을 그쪽으로 옮길 것은 없다(입고수량 열만 거기 없음).
- 수정 API 가 없다(PUT /lots/{id} 없음) · 삭제 API 가 없다. 전표로만 생긴 로트는 `removeDocument` 가 줄이 다 빠지면 지운다.
- `replaceDocument`(구매 · 판매) 는 **없는 로트No. 면 로트를 새로 만든다**(원본은 미등록 로트를 전표에 쓸 수 있는지 못 잼). `createManual` 은 미등록이면 막는다(`등록되지 않은 시리얼/로트No. 입니다`).

2. **서비스**: `create` 가 수량 없이 마스터만 만든다(내역 줄 · stock 0) — `CreateLotRequest` 의 inboundQty 를 선택으로(없으면 0, INBOUND 줄 안 남김). 여러 줄 lotNo 를 한 번에 받는 `lotNos: List<String>`.
   유효기한 기본값은 화면이 넣는다(오늘+5년−1일). `PUT /lots/{id}`(품목 · udi · 유효기한 — 번호는 못 바꿈), `DELETE /lots/{id}`(내역 있으면 400 `처리가 불가능한 코드입니다.` + 자료 `구매: yyyyMMdd-n` 꼴),
   `PATCH /lots/use`(ids, use) 사용중단/재사용. 다른 모듈 · dto-check 영향: `LotResponse` 에 use · udiCode 를 더하면 `CreateLotRequest`/`UpdateLotRequest` 에도(dto-check).
3. **화면** `SerialLotPage`: 제목 `시리얼/로트No.등록`, 격자 6열, 조건 판(유효기한 구간 · 품목 · 시리얼/로트No. · 사용구분 라디오 기본 '사용') — 조회 화면이 아니라 '…등록' 이라 빠른검색칸 + Search(F3) 접힘 꼴(EcListShell 기본).
   신규 창 탭 셋(부가정보 탭은 비어도 칸 이름만), 링크 → 수정 창(번호 잠금 · [H] 공용 이력 — plans/공용.md '붙이는 법'), 수정 창 `사용중단 ▲ 삭제`, 목록 `변경`(일괄 — 유효기한 · 사용구분만 먼저) · `사용중단/재사용 ▲`.
   [보기] 는 내역조회 모달(LotAdjustPage 가 이미 `시리얼/로트No.내역조회` 모달을 갖고 있다 — 같은 꼴로).
   **줄 버튼 출고 · 실사 · 보류는 뺀다**(실사 = /quality/lot-adjust, 출고 = /quality/lot-tx-list 내역입력이 맡는다). `consume` · `hold` API 를 쓰는 곳이 SerialLotPage 뿐이므로 화면에서 빼면 API 도 정리 대상(지우지 말고 보드에 적기).
4. **재고현황(lot-stock)**: 사용중단 플래그가 생기면 `사용중단시리얼/로트포함`(기본 켬) 조건이 그 플래그로 거르게.
5. **흐름 대조**(양쪽 같은 QA 로트): 등록 → 내역 0 · 재고현황 없음 / 내역입력 구매 3 → 재고현황 3.00 / 사용중단 → 등록 목록에서 빠짐 · 재고현황 그대로 / 삭제 시도 → 막힘 / 내역 삭제 → 로트 삭제.
6. `qa/flows/` 에 등록 → 수정 → 사용중단 → 재사용 → 삭제 흐름 하나.

## 못 잼 (원본을 다시 열 것)

- `생성개수` 가 하는 일(번호를 비우고 개수만 넣으면 빨간 테두리로 막혔다 · 번호 1개 + 개수 3 → 1줄). 여러 줄 번호를 넣었을 때 줄 수만큼 생기는지.
- 같은 번호를 두 번 등록할 때의 문구(우리: `이미 존재하는 로트No.입니다: …`). 같은 번호를 **다른 품목**에 쓸 수 있는지.
- [변경] 일괄 저장 결과 · `Fn` 버튼 · [H] 이력 내용 · 바코드(누르지 않음).
- 미등록 로트No. 를 전표(구매 · 판매)에 쓸 때 원본이 로트를 만들어 주는지 — 구매입력 양식에 시리얼/로트 열이 숨겨져 있어 못 잼(`self` 작업자가 양식을 잠깐 펴 줘야 한다).
- 품목vs시리얼재고수량비교 첫 쪽에 A001 이 없었다(쪽 넘김 · 조건 못 봄).
