# 출하지시서 (조회 E040221 · 입력 E040220 · 현황 E040222) — 정리 (2026-10-20 loginaa 실측)

재고 I › 영업관리 › 출하지시서. 우리 화면: `/sales/shipment-order` (`frontend/src/pages/trade/ShipmentOrderPage.tsx`),
현황 `/sales/shipment-order-status` (`ShipmentOrderStatusPage.tsx`). 서버 `backend/.../trade/shipment/` (Shipment 하나가 출하지시 · 출하를 다 맡는다).

**판정: 원본과 크게 다르다 → 약속 7. 이 문서가 정리 단계, 다음 작업자가 다시 하기.**

## 1. 원본의 흐름 — 우리와 가장 크게 다른 곳

출하지시서 화면의 [→ 출하완료] 가 원본의 '출하입력' 을 대신한다. 잔량은 주문 기준(원본은 출하지시서 기준).

## 5. 고칠 순서(다시 하기)

1. **결정 필요(진행자/사용자)**: 출하지시서와 출하를 다른 전표로 가를지. 원본처럼 하려면 `shipment_orders`(출하지시서) ↔ `shipments`(출하, 출하지시서 줄에 잇고 잔량)
   스키마가 바뀐다(마이그레이션 본사 · 테넌트). 가르지 않으면 지금 READY/SHIPPED 를 '출하지시서 진행중/완료' 로만 보이고 출하입력 화면이 출하지시서를 SHIPPED 로 바꾸는 꼴 —
   이 경우 '부분 출하 → 미출하 2.00' 을 못 낸다. 이어지는 원천(원본 판매 / 우리 주문서)도 같이 정한다.
2. 조회 격자를 원본 7열 · 폭으로, 탭 전체 · 결재중 · 확인 · 진행중 · 완료, 진행상태 링크 펼침(진행중 · 완료), 번호 'YYYY/MM/DD -N' 꼴, 조건 판 접힘 · 기본 판 조건만, 아래 단추줄.
3. 입력 창: 단가 · 금액 칸 · 금액 합계 빼기, 출하예정일 기본 오늘, 검증을 '알림' 표 창으로, 저장 뒤 말 없이 닫기, [전표불러오기](베끼기만) · [판매](잇기).
4. 현황: 위 4장 조건 · 열 · 월 계 · 총합계 · 오름차순.
5. 흐름 시험(`qa/flows/`): 주문서 7 → 출하지시서 4 → 수정 5 → 미출하 5 → 출하 3 → 미출하 2 → 삭제.

- 출하 저장이 재고 · 회계에 주는 영향(출하 묶음 몫).
