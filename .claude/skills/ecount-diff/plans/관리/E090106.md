# 급여계산/대장 (E090106) — 정리 단계

2026-10-13 loginaa 실측(관리 작업자). 원본 근무입력 격자 코드도움이 탭 지정 입력으로 안 열려(E090113 BLOCKED)
**원본에 새 대장 · 근무를 넣지 못했다** — 원본에 이미 있는 2026/10 · 2026/09 대장(확정됨)을 **읽기만** 했다.
우리 쪽 숫자는 이번에 화면으로 돌리지 않았고 **코드(PayrollService · SocialInsuranceRates · WithholdingTaxCalculator)로 셈한 값**이다
— 다시 하기 단계에서 QA관리-사원1(QAGL-E1, 지금 기본급 0 · 수당 없음)에 같은 금액을 넣고 화면으로 대조할 것.

## 숫자 규칙 (원본에서 거꾸로 푼 것)

- 부양가족수당 = 기본급 × 1 %. 변동수당 단가: 야근 · 주말 18,000/시간, 연차 180,000/일(근무기록확정 수량 × 단가).
- **과세급여 = 지급총액 − 식대 100,000 − 차량유지비 200,000**(둘 다 비과세). 신문섭 3,030,000 · 성지윤 2,626,000 · 윤지헌 2,828,000 · 최현경 3,232,000 · 정재원 3,694,000.
  **변종호만 4,259,000**(= 4,759,000 − 500,000): 비과세가 200,000 더 있다 — 못 풂. 야근 + 주말 261,000 중 200,000 을 생산직 연장근로 비과세(월 20만)로
  본 것 같지만 정재원(야근 + 주말 159,000)은 전부 과세다. 변종호 사원등록 [사원정보] · [급여지급사항] 탭 · 수당항목 비과세 한도를 다시 볼 것.
  (원천징수부 bracketOf 주석의 '원본 예: 4,259,000' 도 이 값이다.)
- **소득세 = 간이세액표 공제대상가족 1명 칸** — 우리 `tax/simplified-withholding-2024.csv` 와 여섯 명 모두 같다
  (2,620 → 41,400 · 2,820 → 58,520 · 3,020 → 76,060 · 3,220 → 93,170 · 3,680 → 149,220 · 4,240 → 228,000).
- 주민세 = 소득세 × 10 %, 10원 미만 버림(7,606 → 7,600 · 9,317 → 9,310 · 14,922 → 14,920). 우리 localIncomeTax 와 같다.
- **국민연금 = 기준소득월액 × 4.5 %**. 변종호 [기타설정] 기준소득월액 3,800,000 → 171,000. 다른 사람도 기본급 × 4.5 %(135,000 · 117,000 · 126,000 · 157,500 · 144,000).
- **건강보험 = 과세급여 × 3.545 %, 10원 미만 버림**(3,030,000 → 107,413 → 107,410 · 2,626,000 → 93,090 · 4,259,000 → 150,981 → 150,980).
- **장기요양 = 과세급여 × 0.4591 %, 10원 미만 버림** — 건강보험료 × 12.95 % 가 아니다. 신문섭이 가른다:
  과세 3,030,000 × 0.4591 % = 13,910.7 → **13,910**(원본), 건강 107,410 × 12.95 % = 13,909.6 → 13,900. 나머지(12,050 · 19,550 · 16,950 · 14,830 · 12,980)는 둘 다 맞는다.
  우리는 건강보험료 × 비율(PayrollService 214줄) — 방식도 다르다.
- 고용보험 = 과세급여 × 0.9 %, 10원 미만 버림(27,270 · 23,634 → 23,630 · 38,331 → 38,330 · 33,246 → 33,240).
- 공제총액 = 소득세 + 주민세 + 국민연금 + 건강 + 장기요양 + 고용. 실지급액 = 지급총액 − 공제총액.

## 우리와 다른 점 (코드로 셈 — 화면 대조는 다시 하기에서)

신문섭과 같은 금액(기본급 3,000,000 · 부양가족 30,000 · 식대 100,000 · 차량 200,000 · 기준소득월액 3,000,000)을 넣으면 우리 2026/10 은:

| 항목 | 원본 | 우리(SocialInsuranceRates 2026) | 같음? |
|---|---|---|---|
| 소득세 | 76,060 | 76,060 | 같음 |
| 주민세 | 7,600 | 7,600 | 같음 |
| 국민연금 | 135,000 (4.5 %) | 142,500 (4.75 %) | **다름** |
| 건강보험 | 107,410 (3.545 %) | 108,920 (3.595 %) | **다름** |
| 장기요양 | 13,910 (과세 × 0.4591 %) | 14,310 (건강 108,920 × 13.14 %) | **다름**(요율 · 방식) |
| 고용보험 | 27,270 | 27,270 | 같음 |

**사용자 결정 필요**: 원본 loginaa 는 2026/10 급여에도 2025 요율(4.5 · 3.545 · 12.95 %)로 공제한다. 우리는 36회차에 '2026 법정 요율'로 바꿨다
(SocialInsuranceRates 주석). 원본처럼 2025 요율로 되돌릴지, 법정 요율을 유지하고 '남은 것(의도적 차이)' 로 둘지 정해야 한다.
원본 요율이 회사 설정(공제항목 계산식 · 4대보험 요율 설정)에서 오는지도 아직 못 봤다 — 공제항목등록(E090114) 국민연금 · 건강보험 줄의 계산식을 읽어 볼 것.

## 못 잼 (다시 하기에서)

- 원본 CRUD: [신규(F2)] 급여정보입력 → 전체계산 → 확정 → 확정취소 → 삭제. 확정 대장이 둘뿐이고 원본 근무입력이 막혀 새 대장을 안 만들었다.
  새 대장(QA관리-2026/11 같은 이름)은 근무 없이도 만들 수 있으니 다음 사람은 먼저 이것부터 — 단 원본 6명 전원이 계산에 들어가므로 계산 뒤 바로 삭제.
- [전표생성] → 회계 전표(급여 · 예수금 계정, 차대 금액) — 회계1 이체관리 › 급여이체와 이어진다. 누르면 전표가 생기므로 새 QA 대장에서만.
- 변종호 과세 4,259,000 의 비과세 200,000 출처.
- 디자인: 목록 격자 · 급여대장 창 머리 3줄 격자 getComputedStyle.

## 고칠 순서 (제안)

1. 요율 결정을 사용자에게 받는다(위 표).
2. QAGL-E1 에 신문섭 금액을 넣고 우리 2026/10(이미 있으면 새 귀속월) 대장 계산 → 위 표의 '우리' 열을 화면 숫자로 확인.
3. 확정 대장의 칸 글자(계산/수정 · 확정취소 · 전표생성 · Email)를 원본처럼.
4. 급여대장 창 버튼줄(기본(수정불가) · 인쇄 · Excel · 사원별 조회 · 급여계산이 안되는 경우 · 닫기) · 3줄 머리.
